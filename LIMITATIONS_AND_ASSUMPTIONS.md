# VEXORA — Limitations, Scope & System Assumptions

## 1. Scope & Supported Artifacts

### 1.1 Ingestion Formats
- **Portable Document Format (PDF)**: Supports native digital PDFs with vector text and graphic paths, hybrid PDFs containing embedded raster scans, and multi-page documents up to 50 MB.
- **Raster Images**: Supports PNG, JPEG, and TIFF raster scans up to 25 MB per artifact.
- **Unsupported Formats**: Legacy proprietary office formats (DOC, XLS, PPT) must be converted to PDF prior to ingestion to ensure immutable vector geometry.

## 2. Dependencies & Operational Assumptions

### 2.1 OCR System Dependency
- **Optical Character Recognition (OCR)** is executed via `pytesseract` communicating with the underlying Google Tesseract 5.x engine.
- **Honest Absence Behavior**: If the Tesseract executable is not detected on the host system's `PATH`:
  1. Image structural metadata (dimensions, color mode, compression format) is successfully ingested.
  2. The system sets `ocr_available = false` and returns an empty text string with a clear log entry.
  3. **No Synthetic Text**: VEXORA explicitly refuses to fabricate synthetic or placeholder text in place of missing OCR data.

### 2.2 LLM Reasoning Layer
- **Model Target**: Uses Google Gemini (`gemini-2.5-flash`) via the modern official `google-genai` SDK.
- **API Key Configuration**: The LLM layer queries `os.environ.get("GEMINI_API_KEY")`.
- **Zero-Dependency Fallback**: When `GEMINI_API_KEY` is not configured, VEXORA automatically activates its deterministic offline fallback engine. This engine extracts structured JSON fields, executes mathematical verification, quotes verbatim text evidence, and generates executive summaries without external network calls.
- **Traceability Rule**: Every claim made by the LLM is anchored by verbatim quotes from the source document and is accompanied by the mandatory badge:
  > **[AI-assessed, needs review]**

### 2.3 Computer Vision & Image Forensics
- **Error Level Analysis (ELA)** (`IMG-R201`) and **Grid Noise Variance** (`IMG-R202`) are **heuristic filters**, not deterministic proofs of tampering.
- Multiple JPEG compression cycles during normal scanning or email transport can cause uniform noise shifts. Consequently, image forensic outputs are labeled as investigative leads requiring examiner validation.
- **Signature Presence Checking** (`IMG-R203`) verifies whether ink strokes exist within spatial proximity of signature labels. It does not perform full biometric graphology matching against historical reference databases.

## 3. Cryptographic & Data Integrity

### 3.1 Chain of Custody
- Every artifact uploaded to VEXORA receives an immediate SHA-256 cryptographic digest before any parsing or transformation occurs.
- Dossiers generated by VEXORA append a tamper-evident SHA-256 hash calculated over the case metadata, findings registry, and examiner credentials.

### 3.2 Evaluation Isolation
- Seed reference files (`DEMO-REF-01` to `DEMO-REF-03`) and the 20-file ground truth benchmark dataset (`eval/benchmark_dataset/`) are strictly isolated from user-uploaded case artifacts.
- Deleting an active investigation case or document removes the artifact from the database and disk without altering benchmark or baseline models.

## 4. Legal & Regulatory Boundaries

1. **Investigative Support Tool**: VEXORA is an evidence collection and anomaly detection platform designed to assist qualified forensic examiners, compliance officers, and auditors.
2. **Human Attestation**: Automated risk scores (0–100) and severity ratings (Critical, High, Medium, Low) are evidentiary indicators. Final legal determinations of document falsification require review and attestation by a certified forensic document examiner.
3. **Simulated Authentication**: The Google Account authentication demonstrated in the user interface is an interactive demo simulation of OAuth2 identity exchange, purposefully designed without live cloud secrets to facilitate local evaluator testing.
