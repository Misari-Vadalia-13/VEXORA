## 1. Scientific & Forensic Integrity Statement

In digital document forensics and financial cybercrime investigations, false certainty is dangerous. In accordance with ISO/IEC 27037 principles and legal admissibility standards, VEXORA maintains complete transparency regarding its operational scope, algorithmic constraints, and failure modes.

VEXORA is an investigative assistance platform. Its algorithmic findings and AI narratives constitute forensic indicators and anomalies to be evaluated by qualified human examiners, not binding legal verdicts of guilt or fraud.

## 2. Subsystem Boundaries & Technical Limitations

### 2.1 Optical Character Recognition (OCR) Boundaries
- **Tesseract Host Binary Requirement:** High-accuracy OCR requires a functional Tesseract-OCR binary installed on the host system PATH. If absent, VEXORA preserves full platform availability and transparently reports `ExtractionStatus.OCR_UNAVAILABLE` rather than generating artificial text strings.
- **DPI and Degradation Thresholds:** Documents scanned at resolutions below 150 DPI or afflicted by severe motion blur, sensor grain, or non-uniform lighting experience token dropouts and character substitution errors (e.g., misreading `0` as `O` or dropping decimal points).
- **Handwritten Text Recognition (HTR):** VEXORA is optimized for printed, typed, and digital document typography. Freehand cursive writing, scribbled marginalia, and complex signatures are treated as visual image regions rather than transcribed linguistic tokens.

### 2.2 Visual Image Forensics Constraints
- **Digital Graphics vs Camera Sensors:** Error Level Analysis (ELA) and noise variance estimation rely on physical camera sensor characteristics and uniform lossy compression. Pure digital graphics generated by software (e.g. vector-rendered invoices converted to PNG) exhibit mathematically perfect color blocks lacking physical sensor pattern noise (PRNU), which can skew global variance estimators.
- **Multiple Re-compression Cycles:** Documents transmitted via messaging applications (e.g., WhatsApp, Telegram, Slack) undergo repeated aggressive re-compression and downsampling. This smooths out high-frequency discrete cosine transform (DCT) differentials, diminishing the sensitivity of ELA.
- **Geometric Copy-Move Limits:** While VEXORA's RANSAC affine filter (`cv2.estimateAffinePartial2D`) eliminates false alarms on repeating text lines, cloned regions that have been warped with complex non-affine transformations (e.g., thin-plate splines or non-linear mesh deformation) may fall outside the rigid consensus model.

### 2.3 PDF Primitives & Structural Limitations
- **Benign PDF Revision Cycles (`PDF-001`):** Enterprise PDF viewers (Adobe Acrobat, DocuSign, macOS Preview) routinely write new incremental revisions or append `/ModDate` timestamps when an end-user highlights text, signs a field, or saves a form. VEXORA surfaces multiple revisions as investigative signals, not definitive proof of malicious tampering.
- **Corporate Typographic Standards:** Legitimate corporate brand guidelines routinely pair distinct font families for decorative headers and tabular body items. Typographic divergence rules (`RULE-VIS-001`) flag these as structural observations that require analyst contextual review.

### 2.4 Language & Locale Assumptions
- **Latin Typography & Western Formats:** VEXORA's heuristic parsers, regular expressions, and date models are calibrated for standard Western business documents in the English language. Non-Latin scripts (Cyrillic, Arabic, Chinese, Devanagari) require localized dictionary models.
- **Ambiguous Date Formats (`RULE-CTX-003`):** Numeric date notations such as `03/04/2026` are parsed using standard Western conventions (`DD/MM/YYYY` or `MM/DD/YYYY`). Without explicit regional metadata, temporal sequence checks may require analyst confirmation.

### 2.5 Single-Document vs Multi-Document Blind Spots
- **Internally Flawless Forgeries:** A fraudulent invoice that presents valid arithmetic, authentic fonts, and no visual splices—but contains an unauthorized banking routing number or duplicate invoice number—cannot be detected in isolation. Such anomalies can only be uncovered by VEXORA's cross-document correlation engine when compared against procurement counterparts.

### 2.6 Persistence & Scaling Limits
- **Single-Node SQLite Architecture:** VEXORA utilizes a local SQLite database (`backend/vexora.db`) for zero-dependency portability and turnkey hackathon evaluation. While SQLite supports thousands of queries per second, concurrent multi-user write operations queue behind SQLite's file-level lock. For large-scale enterprise deployments, migration to PostgreSQL or Google Cloud Spanner is recommended.
- **Audit Hash-Chaining Concurrency:** Hash-chaining relies on sequential block generation (`prev_hash`). In concurrent write bursts, synchronization locks serialize append operations to guarantee tamper-proof linear chain integrity.

### 2.7 Optional AI Subsystem Operational Limits
- **API Key & Quota Dependencies:** AI-assisted explanation requires external provider credentials (`VEXORA_LLM_API_KEY`). If unconfigured or exhausted (HTTP 429), VEXORA falls back 100% to deterministic summaries without degradation of core forensic capabilities.
- **Strict Zero-Authority Mandate:** Large Language Models are explicitly prevented from asserting findings or determining fraud. All AI outputs carry mandatory investigator disclaimers and require quote verification against source document text.

## 3. Summary of Operational Mitigations

| Boundary | Impact | VEXORA Architectural Mitigation |
| :--- | :--- | :--- |
| **Missing Tesseract** | Scanned text unparsed | Clear `ExtractionStatus.OCR_UNAVAILABLE` status; no fabricated placeholder text. |
| **Repetitive Text False Alarms** | Copy-move false alarms | RANSAC affine consensus (`cv2.estimateAffinePartial2D`) with $N \ge 6$ inlier threshold. |
| **Rotated Scans** | OCR text scrambled | Automated OpenCV deskewing via `minAreaRect` baseline alignment. |
| **Prompt Injection Attacks** | Malicious instructions in documents | Encapsulation in `<untrusted_document_content>` XML tags and heuristic neutralization. |
| **Storage Corruption** | Evidence altered on disk | Real-time cryptographic SHA-256 integrity verification (`GET /api/documents/<id>/integrity`). |
| **Audit Log Tampering** | Evidence altered in database | Linear SHA-256 hash chaining (`verify_audit_trail_integrity()`) detecting row edits/deletions. |
| **Multi-User Data Exposure** | Analyst A sees Analyst B's cases | Cascading IDOR security validation across all case, document, and finding endpoints. |
